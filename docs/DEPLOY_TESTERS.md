# Hosted tester deployment (EXT-130)

Invited team members and faculty only. Fictional stories only — never a real victim or a real event. Text chat only: the cloud backend runs `LLM_PROVIDER=mock`, `ASR_PROVIDER=mock` and `TTS_PROVIDER=none`; voice stays on the laptop demo. Scope and teardown are recorded in `docs/EXTERNAL_DECISIONS.md` (EXT-130).

| Piece | Host | Config |
|---|---|---|
| Backend (FastAPI) | Render free web service | `render.yaml` |
| Database | Supabase free PostgreSQL | `docs/LOCAL_SETUP.md` (Supabase section) |
| Executive console | Vercel, `/` (`/exec` redirects to it) | `vercel.json` |
| Victim web app | Vercel, `/victim` | `vercel.json`, `mobile/app.json` (`experiments.baseUrl`) |
| Victim Android app | EAS Build, `preview` profile (APK) | `mobile/eas.json` |

No secret is committed. Every value below is entered in a provider dashboard or a local `.env`.

## 1. Database (Supabase)

1. Create an empty project. Follow the preflight in `docs/LOCAL_SETUP.md`.
2. From **Connect**, copy the **Session pooler** URL (port 5432). Render has no IPv6 egress, so the direct `db.<ref>.supabase.co` host may be unreachable; port 6543 (transaction pooler) is rejected by configuration.
3. Use the `postgresql+asyncpg://` scheme. TLS (`ssl=require`) is added automatically.

## 2. Backend (Render)

1. New → Blueprint → this repository. Render reads `render.yaml`.
2. Set `DATABASE_URL` (step 1) and `FRONTEND_ORIGIN` (the Vercel origin from step 3, e.g. `https://<project>.vercel.app`, no trailing slash). `SECRET_KEY` is generated by Render; the backend refuses to start with the committed default or a key shorter than 32 characters.
3. Deploy. Start runs `alembic upgrade head`, then uvicorn. Check `https://<service>.onrender.com/health`.
4. Free tier sleeps after idle time; the first request can take about a minute and open console WebSockets drop when it sleeps. Open `/health` before a test session.

## 3. Seed executive accounts

From the laptop, against the Supabase URL, with the remote-seed confirmation described in `docs/LOCAL_SETUP.md` and `SEED_PASSWORD` set in your shell (never in chat or Git). This creates `exec1`, `exec2`, `sup1`. Hand passwords to testers privately.

## 4. Console and victim web (Vercel)

1. Import the repository. Root directory: repository root. Vercel reads `vercel.json`.
2. Node.js version: 24.x (the `engines` field in both packages).
3. Environment variables (Production):

| Variable | Value |
|---|---|
| `VITE_API_URL` | `https://<service>.onrender.com` |
| `VITE_WS_URL` | `wss://<service>.onrender.com` |
| `EXPO_PUBLIC_API_URL` | `https://<service>.onrender.com` |
| `EXPO_PUBLIC_VOICE` | `off` |
| `EXPO_PUBLIC_TESTER_BUILD` | `on` |

4. Deploy, then put the Vercel origin into Render's `FRONTEND_ORIGIN` and redeploy the backend.

## 5. Android APK (EAS)

```powershell
cd mobile
$env:EXPO_PUBLIC_API_URL = "https://<service>.onrender.com"
$env:EXPO_PUBLIC_VOICE = "off"
$env:EXPO_PUBLIC_TESTER_BUILD = "on"
npx eas-cli build --platform android --profile preview
```

`eas-cli` needs your own Expo login. Share the APK link only with invited testers. iPhone users use `/victim` in the browser.

## 6. Hosted AI signals and reviewed wordings (optional, EXT-132 / EXT-133)

Wordings need no Space: set `LLM_PROVIDER=variants` in Render and the backend uses the
lead-approved English variants and Hinglish strings in `ml/dialogue/variants.py` (spoken only
once their review status is APPROVED). No model writes text to a victim at runtime.

The Space below runs the advisory MuRIL signal for officers.
Needs a Hugging Face account at least 30 days old with a verified email (free ZeroGPU:
2 Spaces, 5 GPU-minutes per day; when the quota runs out every turn falls back safely).

1. Log in: `hf auth login` (in the `sahay-ml-models` environment).
2. Upload the classifier checkpoint to a **private** model repository (never public: its
   training data licences are pending, EXT-133):
   `hf upload <you>/sahay-signals <training root>/task7b/checkpoints/C-seed-13 . --private`
3. Create a Space: SDK **Gradio**, hardware **ZeroGPU**, visibility **Private** if offered
   (otherwise Public: the endpoint refuses to answer without the key). Upload the folder:
   `hf upload <you>/sahay-models hf-space . --repo-type space`
4. In the Space settings add:
   - secret `SAHAY_SPACE_KEY`: a random value of 32+ characters
   - secret `HF_TOKEN`: a read token that can read `<you>/sahay-signals`
   - variable `SAHAY_SIGNALS_REPO`: `<you>/sahay-signals`
5. In Render add:

| Variable | Value |
|---|---|
| `LLM_PROVIDER` | `variants` |
| `SIGNALS_PROVIDER` | `remote` |
| `LLM_REMOTE_URL` | `https://<you>-sahay-models.hf.space` |
| `LLM_API_KEY` | an HF token that can access the Space (secret) |
| `LLM_REMOTE_KEY` | the same value as `SAHAY_SPACE_KEY` (secret) |
| `SIGNALS_TIMEOUT_SECONDS` | `20` (background only; the GPU queue adds delay, a timeout just means no signal) |

6. Check: start a session and confirm in the console that the AI signal panel appears. If the
   Space is asleep, the first cycles show no signal while it wakes.

Teardown also deletes the Space and the `sahay-signals` repository.

## Tester briefing

Give every tester this, outside the app:

- Use an invented story. Never describe a real event, a real person or your own experience.
- The assistant is an AI. A test officer may or may not be watching at the time you test.
- If you, or anyone, needs help for real, do not use this app. Call **112** (emergency), **14416** (Tele-MANAS, national mental health helpline, free, 24×7) or, for an atrocity against a member of a Scheduled Caste or Scheduled Tribe, **14566** (National Helpline Against Atrocities).

## Teardown

When the test window ends: delete the Render service, the Vercel project and the Supabase project; revoke the APK link; rotate seed passwords.
